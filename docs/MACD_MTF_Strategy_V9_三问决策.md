# V9 三个核心问题的决策建议

> 文档用途：针对专家组提出的三个具体问题给出明确决策建议  
> 基线：V8 / A 方案，回测 `+92.38%`，MDD `10.69%`，盈利因子 `2.74`

---

## 问题一：A 是否直接作为实盘基线？

### 结论：建议直接切换，但分两步执行

**支持直接切换的理由：**

V8 / A 相较基线的提升是全维度的，不存在"收益提升但其他指标恶化"的情况：

| 指标 | 基线 | A / V8 | 变化 |
| --- | --- | --- | --- |
| Return | `+76.90%` | `+92.38%` | `+15.48pp` ✅ |
| 盈利因子 | `2.26` | `2.74` | `+0.48` ✅ |
| MDD | `13.15%` | `10.69%` | `-2.46pp` ✅ |
| 胜率 | `69.08%` | `71.43%` | `+2.35pp` ✅ |
| 交易数 | `498` | `511` | `+13` ✅ |

四个核心指标全部改善，且交易数反向增加（说明是精准去毒，不是过度过滤），这种情况不需要再等更多验证。

同时两个 bug（过滤器绕过 + CVD 上下文传参缺失）已经修复，当前回测结果是基于**真实过滤逻辑**跑出来的，不存在"测试数据失真"的风险。

**建议分两步执行的原因：**

直接切换不等于全仓切换，建议：

- **第一步：** 以当前 V8/A 参数运行实盘，但将 `default_target_portion` 临时从 `60%` 降到 `45%`，观察 1~2 周实盘信号与回测信号的一致性
- **第二步：** 确认实盘信号质量与回测一致后，恢复到 `60%` 正常仓位

这不是对 A 方案的不信任，而是对**实盘滑点、数据时效、流动性差异**的标准性缓冲。加密市场的实盘与回测之间总存在微小差距，两步执行可以让这个差距在低暴露状态下被观察到。

**不建议做的事：**

- 不建议再跑一轮 OOS（滚动窗口）验证后才切换，当前样本量（511 笔）已足够，再等会错过实盘窗口
- 不建议保留 B 方案做 A/B 并行实盘，B 方案已明确证明是过度过滤

## 问题二：是否还要加时间段风控？

### 结论：建议加，但只加轻量级版本，不做复杂时段系统

**为什么建议加：**

V8 文档明确提到：
> 当前回撤簇仍集中在 `2026-03-01 ~ 2026-03-04`，存在"时间聚集"特征

历史大亏单也呈现时段聚集（UTC 15:xx ~ 16:xx 多次出现），这不是随机分布，是可以被干预的系统性特征。

不加时段风控，MDD 的尾部就永远依赖于"某几天没有同时爆亏"这个运气因素。

**建议只做轻量级版本（两条规则）：**

**规则 1：美股开盘前后降仓**

```json
"session_risk": {
  "us_premarket_window": { "utc_start": "14:30", "utc_end": "16:00" },
  "position_scale": 0.65
}
```

- 只降仓 35%，不禁止开仓
- 该时段流动性剧烈，VWAP 参考稳定性最差
- 仅适用于 `short_dual_pressure` 和 `flip_bullish` 主力信号

**规则 2：连续亏损触发日内冷却**

```json
"intraday_cooldown": {
  "trigger_consecutive_losses": 2,
  "cooldown_minutes": 90,
  "reset_at_utc": "00:00"
}
```

- 当日内连续止损 2 笔，暂停 90 分钟不开新仓
- 不是永久降仓，只是局部冷却
- 防止在单边行情中连续被扫

**不建议做的复杂版本：**

- 不建议建立完整的 UTC 时段权重表（过于复杂，参数过拟合风险高）
- 不建议对所有信号类型都加时段限制，只对历史上集中爆亏的信号状态加
- 不建议用固定时间段禁止开仓，这会显著减少信号数量

**预期效果：**

两条轻量规则的预期效果是将 MDD 从当前 `10.69%` 压缩到 `8%~9%` 区间，同时对收益的影响应该在 `-3%~-5%` 以内（仅仓位缩减效应）。

这个代价是可以接受的，因为 MDD 从 10.69% 降到 8% 以下，实盘心理承受难度和仓位管理压力都会显著下降。

## 问题三：4H shrink exit 是否还要再提前一点？

### 结论：建议小幅提前，但只调一个参数，不改核心逻辑

**当前 shrink exit 参数：**

```
exit_4h_shrink_bars    = 2
exit_4h_min_shrink_pct = 0.20
exit_4h_require_profit = true
```

含义：至少 2 根 4H bar 连续收缩，且收缩幅度 ≥ 20%，且当前持仓盈利，才触发提前离场。

**问题所在：**

`exit_4h_require_profit = true` 是当前最主要的限制——在未盈利时无法触发 shrink exit，只能等止损。这已经在 V9 优化建议 E1 中被提出过。

但"提前离场"和"降低 shrink 门槛"是两个不同的方向：

| 操作 | 效果 | 风险 |
| --- | --- | --- |
| 降低 `exit_4h_min_shrink_pct`（如 0.15）| 更早触发，更多单子被提前离场 | 可能截断真正有利的盈利走势 |
| 将 `exit_4h_shrink_bars` 从 2 降到 1 | 更快触发，只需 1 根 bar 收缩 | 单根 bar 收缩可能是噪音，误触率高 |
| 放开 `exit_4h_require_profit` | 弱亏损时也可离场 | 需要同步提高 `shrink_pct` 要求以防止误触 |

**建议方案：只改一个参数**

```json
"exit_4h_require_profit": false,
"exit_4h_min_shrink_pct": 0.30,
"exit_4h_weak_loss_threshold": -0.001
```

- 放开盈利要求，允许小亏离场
- 同步将 shrink 门槛从 `0.20` 提高到 `0.30`（避免亏损时因为小幅收缩就过早离场）
- 只有在亏损 < 0.1% 且 shrink ≥ 30% 时才触发，不是无条件放开

**不建议动的参数：**

- `exit_4h_shrink_bars = 2` 保持不变，1 根 bar 的收缩可靠性不足
- `exit_4h_min_shrink_pct` 不建议低于 `0.20`，否则会误触太多正常盈利单的离场

**预期效果：**

当前 `stop_loss_intrabar` 是主要亏损 exit_reason，修改后部分原本会等待止损的单子可以在小亏状态下提前离场，单笔亏损的绝对金额应有所收窄，但总交易数和胜率影响较小。

## 三个问题的综合决策

| 问题 | 建议决策 | 执行顺序 |
| --- | --- | --- |
| A 是否直接作为实盘基线 | ✅ 直接切换，分两步降仓 → 恢复 | 立即执行 |
| 是否加时段风控 | ✅ 加轻量版（时段降仓 + 连亏冷却） | 第 1 批验证 |
| shrink exit 是否提前 | ✅ 放开盈利要求 + 同步提高 shrink 门槛 | 第 1 批验证 |

三个方向没有互相冲突，可以在同一轮回测中同时验证，合并为 V9 候选 A。
