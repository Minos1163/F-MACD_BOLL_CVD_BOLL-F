## Q4 答案 + 修复（今天执行，风险最低）

**IOC 未成交是纯执行层问题，与昨天的方向错误无关，可立即修**

```python
# 问题：IOC LIMIT executedQty=0 的根本原因
# IOC = Immediate Or Cancel，限价单到达交易所时：
# 如果当前 orderbook 没有可以立即成交的对手盘（价格不匹配）→ 直接取消

# 本次两笔的情况：
# AVAXUSDT  SELL score=0.716 → 限价可能比 bid 高，卖单挂高了
# RENDERUSDT SELL score=0.715 → 同上
# 两笔同时 executedQty=0 说明是系统性问题（限价偏离），不是偶发

# 修复路径：三档退化（已在历史配置里存在，确认是否真的生效）
def _execute_entry_order(
    self,
    symbol:    str,
    side:      str,
    quantity:  float,
    ref_price: float,    # 策略计算的参考价
    score:     float,
) -> dict:
    """
    三档执行路径：
    1. IOC 限价（主路径，最优滑点控制）
    2. IOC 限价宽一档（retry，扩大 slippage）
    3. 市价单（兜底，仅高分信号）
    """
    cfg = self.config.execution

    # ── 档位 1：IOC 限价（当前默认）─────────────────────────
    ioc_price = self._calc_ioc_price(
        ref_price, side,
        slippage_bps=cfg.open_ioc_retry_step_bps    # 当前配置值
    )

    result = self._place_ioc_limit(symbol, side, quantity, ioc_price)

    if result.executed_qty > 0:
        return result   # 成交，结束

    # ── 档位 2：IOC 宽档 retry（+15bps）────────────────────
    for retry in range(cfg.open_ioc_retry_times):   # 当前 3 次
        wider_price = self._calc_ioc_price(
            ref_price, side,
            slippage_bps=(cfg.open_ioc_retry_step_bps * (retry + 2))
        )
        result = self._place_ioc_limit(symbol, side, quantity, wider_price)

        if result.executed_qty > 0:
            self._log_info(
                f"[IOC_RETRY] {symbol} filled on retry {retry+1} "
                f"price={wider_price:.6f}"
            )
            return result

    # ── 档位 3：市价单兜底（仅 score >= 0.72 且 ATR 条件）──
    if score >= cfg.entry_market_fallback_min_score:   # 当前 0.68
        current_price = self._get_latest_price(symbol)
        slippage = abs(current_price - ref_price) / ref_price

        if slippage <= cfg.entry_market_fallback_max_slippage_bps / 10000:
            self._log_info(
                f"[MARKET_FALLBACK] {symbol} IOC failed, "
                f"fallback to market slippage={slippage:.4f}"
            )
            return self._place_market_order(symbol, side, quantity)

        self._log_info(
            f"[MARKET_FALLBACK_BLOCKED] {symbol} slippage={slippage:.4f} "
            f"exceeds max={cfg.entry_market_fallback_max_slippage_bps}bps"
        )

    self._log_info(f"[IOC_ALL_FAILED] {symbol} all IOC retries exhausted, no fill")
    return OrderResult(executed_qty=0, status="canceled")
```

```
  因为 SHORT + green_bar_shrinking 目前是 SHADOW（不是 BLOCK）
  score=0.816 足够高，如果 probe_floor_rescue 开启，会实际下单

验证链路：
  1. combo_hard_block 是否覆盖了这个 XRPUSDT 的信号组合？
     → 需要知道 XRPUSDT 的 direction + signal_1h
  2. 如果是 SHORT + green_bar_shrinking → 当前是 SHADOW，不 live
  3. 如果 probe_floor_rescue 开启 → 会绕过 SHADOW → 开仓

正确顺序：
  combo_block 验收通过（WR >= 60% in 24H）
    → 确认 SHADOW 信号确实不产生亏损
    → 再开 probe_floor_rescue（只对 PASS 路径的信号生效）
    → probe_floor_rescue 不能救 SHADOW/BLOCK 信号的仓位

代码强制约束：
```

```python
# src/app/fund_flow_bot.py — _apply_probe_floor_rescue()

def _apply_probe_floor_rescue(
    self,
    signal_score:    float,
    target:          float,
    combo_action:    str,    # "PASS"|"PROBE"|"SHADOW"|"BLOCK"
) -> float | None:
    cfg = self.config.probe_floor_rescue

    if not cfg.enabled or cfg.shadow_mode:
        return None

    # ── combo_action 检查：只救 PASS 路径 ──────────────────
    if combo_action in ("SHADOW", "BLOCK"):
        self._log_debug(
            f"probe_rescue skipped: combo_action={combo_action}"
        )
        return None   # SHADOW/BLOCK 的信号不允许被 rescue

    if signal_score < cfg.min_score_threshold:
        return None

    probe_min = cfg.probe_min_open_portion   # 0.042
    if target >= probe_min:
        return target

    return probe_min
```
